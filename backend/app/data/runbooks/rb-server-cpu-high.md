## 现象

CPU 5 分钟平均持续 >90%，接口延迟升高，可能伴随内存上涨。

## 排查步骤

1. 查 top/进程列表，定位高 CPU 进程。
2. 查最近发布、定时任务、批处理是否异常。
3. 查 GC/线程池/连接池指标。
4. 查是否被压测或异常流量。

## 处置

1. 若是异常进程，先限流/降级/重启单个无状态服务（change_low，需确认）。
2. 若是容量不足，评估扩容或拆分。
3. 若是代码问题，回滚最近发布。
4. 处置后回读 CPU、内存、接口错误率。

## 回滚

- 回滚发布：保留上一版本镜像/包，回滚后验证核心接口。
- 重启服务：确认无状态、无本地会话丢失。

## 风险与注意事项

- 不要直接重启数据库或有状态中间件。
- 先降级再扩容，避免把异常流量放大。
