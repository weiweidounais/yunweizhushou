## 1. 产品形态判断

- 产品类型与核心任务：面向数据中心值班工程师的个人运维助理。核心任务是「告警/问题 → 查上下文 → 根因与证据 → 处置建议 → 审批后单设备变更 → 回读验证 → 审计」。
- 核心交互：多轮对话 + 动态工具调用 + 人工审批。不是一次生成，也不是固定流水线。
- 开发路径：**A 后端先行**。
  - 理由：这个产品最难的不是界面，而是两件事——诊断结论是否可信（证据、根因、不知道就说不知道），以及审批/执行/审计的状态机是否真的拦得住危险操作。先把这两条用 API 和测试打穿，再接正式前端，返工最少。
  - 与手册默认的差异：手册建议「多轮对话/人工确认」默认纵向切片；本次先做临时验收界面，阶段 3 再做正式 Next.js 前端。取舍与影响见第 4 节。
- 验收界面：**临时验收界面**（单个 HTML，FastAPI 静态挂载；阶段 3 开始时废弃，替换为 Next.js 正式前端）。
  - 覆盖：对话、工具/证据卡片、变更计划与审批按钮、审计列表。
  - 不做：正式视觉系统、移动端适配、复杂信息架构；阶段 2 是否表第 4、7 项对它填 N/A。
- 上线套餐：**暂不涉及**。D9 已定：本次只做本地可运行 demo，阶段 3 收尾，不部署。
- 当前阶段范围：V1.0-demo（D10）——只读诊断、变更前评估、审批后单设备变更、审计、手动执行模式；不做手动巡检、定时、记忆、MCP、批量、多用户。

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 未来何时重新评估 |
| --- | --- | --- | --- | --- |
| 多轮/审批类默认「纵向切片」 | 后端先行 + 临时 HTML 验收界面；阶段 3 再上 Next.js | 先验证诊断质量与审批/审计状态机；临时界面只服务验收，避免在 API 未稳定时搭前端框架 | 阶段 3 会重做界面；临时界面不做移动端/正式视觉 | 阶段 3-0《前端适配声明》时评估；如果交互问题提前暴露，可提前切纵向切片 |
| SQLite + SQLAlchemy + Alembic | SQLite + SQLAlchemy `create_all` + `schema_version` 表 | 单用户本地 demo，表结构还会随子阶段调整；先不引入迁移工具 | 未来改表需要手工迁移；数据量小、可重建 | 出现真实用户数据或第二次结构变更时引入 Alembic |
| SSE 流式对话 | 阶段 2 先用「提交 + 查询/等待」的普通请求返回完整结果 + 工具事件列表 | 先把 Agent 主链路和审批状态机跑通；临时界面可以等待 10–20 秒 | 对话过程中看不到逐 token 输出；工具进度在结果里一次性展示 | 阶段 3 正式前端时补 SSE（PRD FR-002） |
| 真实 Prometheus/Alertmanager/NetBox | 内置模拟 fixtures + Provider 接口 | 没有现成只读账号/网络；演示阶段先用可控数据 | 不能反映真实环境的数据质量 | 有真实只读账号后，换 Provider 实现，不改工具层 |
| 真实设备变更 | 模拟执行器 + 手动执行模式 | 演示阶段不能碰真实设备；安全第一 | 只能验证审批/审计/回读流程，不能验证真实厂商 API | 有 Ansible/AWX 或厂商 API 后接真实 ChangeProvider |
| 手动巡检（PRD FR-040 P0） | 暂缓到 V1.1 | 与本次「诊断 → 审批 → 执行 → 审计」主链路无关，避免挤压核心链路 | 本次 demo 没有巡检页 | V1.1 与定时巡检一起做 |
| 跨会话记忆、定时、MCP、批量、多用户 | 不做 | PRD V1.0 已明确后移；D10 | 本期没有这些入口 | V1.1/V2.0 按 PRD 版本规划 |

## 5. 强制底线检查

- 密钥与隐私：**计划通过**。`MODEL_API_KEY` 只进 `backend/.env`（根 `.gitignore` 已忽略）；`.env.example` 只放占位；不写进前端、日志、证据包；不在对话中回显。
- 数据与任务可恢复：**计划通过**。会话、消息、工具调用、变更计划、审批、审计都落 SQLite；`scripts/restart-check.sh` 实现 start/write/read/stop，阶段 2 自检会杀进程验证。
- 输入输出校验：**计划通过**。所有 API 用 Pydantic 请求/响应模型；模型输出用 Pydantic 强校验；错误统一 `{"error": {"code", "message"}}`。
- 错误与日志边界：**计划通过**。模型调用处理超时、失败、有限重试、SDK 初始化失败；日志不记密钥、密码、完整用户内容；错误不返回堆栈。
- 测试与真实模型验收：阶段 2-1/2-2 先跑 mock 自动化测试（至少 5 条，覆盖 Agent 分发、策略、审批绑定、审计链、降级）；阶段 2-3 用 DeepSeek 跑真实冒烟，冒烟脚本自动写 `docs/evidence/阶段2-3/冒烟记录.md`；无 Key 时是否表第 3 项写「待验」。
