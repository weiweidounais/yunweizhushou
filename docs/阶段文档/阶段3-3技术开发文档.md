# 阶段 3-3 技术开发文档（前端：完整交互与质量）

> 配套：《前端适配声明》、PRD V3、前端手册第 22 节子阶段 3/4。
> 本阶段收口正式前端：历史会话、刷新恢复、取消/重试、移动端、浏览器检查与质量；不做部署（阶段 4）和新增业务能力。

## 1. 本阶段目标

- 工作台有「最近会话」，可切换历史会话。
- 刷新后恢复会话消息和最近一次变更计划，不把已完成的变更是丢掉。
- 诊断进行中可「停止」等待；失败/连不上时有「重试」。
- 1440/1280/768/390 全流程可用；Console 无错误、无 4xx/5xx。
- 前端测试、Lint、类型、构建通过；真实模型冒烟通过。

## 2. 范围

### 本阶段包含

- 后端新增 `GET /api/sessions?limit=` 最近会话；`GET /api/sessions/{id}` 返回 `latest_change_plan`。
- 前端 `SessionList`（最近会话）、刷新恢复最近变更卡片。
- `AbortController` 停止等待；错误条重试；状态 `cancelled`。
- 手机抽屉同时放最近会话和示例；390/768/1280/1440 截图。
- 浏览器 Console/网络检查、空/错/加载状态、错误重试验证。
- 后端 28 条、前端 12 条测试；真实冒烟。

### 本阶段不包含

- SSE（本迭代明确不做；提交+等待+停止/重试）；
- 部署、HTTPS、真机证书（阶段 4；D9 本轮不部署）；
- 登录、多用户、双人复核；
- 真实设备执行。

## 3. 用户流程

1. 打开工作台 → 左侧「最近会话」列出历史；点任意会话切换。
2. 诊断中显示「停止」；点停止 → 状态「已停止」，提示后端可能仍在执行。
3. 后端不可用/请求失败 → 错误条 + 「重试」；恢复后重试成功。
4. 完成一次变更后刷新 → 消息、结论、最近一次变更卡片恢复。
5. 手机 390 宽打开抽屉 → 最近会话 + 示例，可切换和发起。

## 4. 页面状态矩阵

| 状态 | 触发 | 页面表现 |
| --- | --- | --- |
| idle | 新会话 | 空状态 + 示例 |
| running | 请求中 | 活动提示 + 停止 |
| cancelled | 用户停止 | 已停止说明，保留用户输入 |
| failed | 网络/500 | 错误条 + 重试 |
| stale | 刷新 | 重新拉取会话 + 最近变更 |
| waiting_user | 变更待审批 | 计划卡片 + 批准/拒绝 |
| succeeded | 诊断/执行完成 | 结论/计划结果 |
| disconnected | 代理/后端断开 | 错误条提示检查 8020 |

## 5. 接口契约

- `GET /api/sessions?limit=8` → `{sessions:[{id,title,created_at,updated_at,message_count}]}`
- `GET /api/sessions/{id}` → `SessionView` + `latest_change_plan`
- `POST /api/sessions/{id}/chat` 支持浏览器 `AbortSignal`
- 变更/审计接口沿用 3-2。

## 6. 实现方案

- 后端：`SessionSummary`、最近会话查询、`get_session` 返回最近计划；
- 前端：`SessionList`、`restoredPlan`、`abortRef`、`lastQuestion`、错误重试；
- 状态：`cancelled` 加入统一状态；
- 测试：状态映射、API 错误、变更卡片、审计页；后端会话列表/最近计划测试；
- 浏览器：4 个宽度截图、刷新恢复、取消、错误重试、Console 检查。
