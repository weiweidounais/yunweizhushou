# 阶段 3-2 技术开发文档（前端：变更、审批与审计）

> 配套：《前端适配声明》、PRD V3、前端手册第 22 节子阶段 2/3。
> 本阶段把后端已验收的变更/审批/执行/回读/审计能力接进正式前端；完整历史、刷新恢复与移动端打磨在 3-3。

## 1. 本阶段目标

- 工作台能发起变更，展示变更计划（资产、参数、理由、影响、回滚、plan_hash）。
- 批准/拒绝可操作；批准后由确定性代码执行 + 回读，界面显示结果。
- 审计页展示 proposed/approved/executing/executed/verified/rejected/denied，哈希链可校验。
- 1440/1280/768/390 可用；手机能审批和看审计。

## 2. 范围

### 本阶段包含

- `ChangePlanCard`：待审批按钮、状态、执行/回读结果、模拟执行标识、审计入口；
- `Workbench` 接入审批：`POST /api/changes/{id}/approve` + 发送「已批准 plan_id=…」触发确定性执行；
- 拒绝：`POST /api/changes/{id}/reject`，卡片置已拒绝；
- 示例面板增加「变更演示：隔离 core-sw-01 的 Gi1/0/24」；
- `/audit` 正式页：审计表、链校验、刷新、空/错误/加载态、移动端横向滚动；
- 单测：ChangePlanCard、AuditView；总前端测试 12 条；
- 真实模型变更链路冒烟。

### 本阶段不包含

- 会话历史列表、刷新后变更卡片恢复（3-3）；
- SSE、取消/重试完整交互（3-3）；
- 登录、多用户、部署（4/5）；
- 真实设备执行（仍是模拟执行器）。

## 3. 用户流程

1. 工作台点「变更演示」→ 发送；
2. 6–12 秒后出现诊断 + 变更计划卡片（待审批）；
3. 点「批准」→ 后端创建审批 → 自动发送「已批准 plan_id=…」；
4. 确定性代码执行 + 回读 → 新卡片显示「已回读验证」、执行/回读摘要；
5. 点「查看审计记录」或顶部「审计」→ 看到 proposed/approved/executing/executed/verified 和链校验；
6. 手机 390 宽可完成批准与审计查看。

## 4. 页面状态矩阵

| 状态 | 触发 | 页面表现 |
| --- | --- | --- |
| waiting_user | 变更 `pending_approval` | 计划卡片 + 批准/拒绝 |
| approved | 点击批准成功 | 卡片置已批准，按钮消失，开始执行 |
| running | 执行/回读中 | 按钮禁用；等待结果 |
| succeeded | 执行成功 | 新卡片显示执行摘要 |
| verified | 回读通过 | 新卡片显示「已回读验证」+ 检查项 |
| failed | 执行/回读失败 | 错误状态 + 原因 |
| rejected | 点击拒绝 | 卡片置已拒绝，不执行 |
| busy | 审批请求进行中 | 按钮禁用，防重复提交 |

## 5. 接口契约

- `POST /api/changes/{plan_id}/approve` → `{approval_id, expires_at, plan}`
- `POST /api/changes/{plan_id}/reject` → `{plan}`
- `GET /api/changes/{plan_id}`（已有，暂未用）
- `GET /api/audit?limit=100` → `{records, chain:{valid,checked,broken_at}}`
- `POST /api/sessions/{id}/chat` 的 `change_plan` 字段提供计划/状态/执行/回读；
- 批准后的执行由后端确定性代码完成，不让模型重新提议。

## 6. 实现方案

- `features/chat/components/ChangePlanCard.tsx`；
- `Workbench` 的 `busyPlanId`、`handleApprove`、`handleReject`；
- `MessageBubble` 支持 `plan` 渲染；
- `features/audit/AuditView.tsx` + `/audit` 页面；
- API 客户端已有 `approveChange`/`rejectChange`/`audit`；
- 审计时间由后端从 UTC 转本地展示。

## 7. 验收标准

- [ ] 变更卡片字段完整，待审批有批准/拒绝；
- [ ] 批准后执行 + 回读成功，卡片显示「已回读验证」；
- [ ] 拒绝后不执行；
- [ ] 审计页看到 5 条链路，哈希链通过；
- [ ] 1440/1280/768/390 检查；
- [ ] 前端 12 条测试、lint/typecheck/build 通过；
- [ ] 真实模型变更冒烟通过；
- [ ] 没有未审批执行、没有真实设备调用。

## 8. 风险与回退

- 执行器是模拟的；界面必须标「模拟执行」，不得让用户误认为真实设备已操作。
- 批准后由确定性代码执行，模型不参与执行，降低绕过审批风险。
- 刷新后变更卡片不恢复（会话消息只有文字/结论）；审计记录保留。3-3 补恢复。
- 审批一次性/15 分钟过期/plan_hash 绑定由后端保证；前端只调用接口。
