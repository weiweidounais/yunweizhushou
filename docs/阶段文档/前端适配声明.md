# 前端适配声明

## 1. 项目判断

- 产品类型：面向数据中心值班工程师的个人运维助理（Agent）。
- 主要用户：单用户、本地/值班工作站使用。
- 主要终端：桌面 Web 为主，移动 Web 可查看与审批。
- 新项目或已有项目：已有后端与临时验收界面；正式前端为新建。
- 本阶段业务目标：把已验收的后端能力（只读诊断、变更审批、模拟执行、回读、审计）做成正式 Next.js 前端；不新增业务能力。

## 2. 输入资料

- PRD：已读取（`docs/PRD/PRD.md` V3）。
- 技术适配声明与决策台账：已读取。
- 阶段 2 界面类型：**临时验收界面**（`backend/static/index.html`），阶段 3-1 起废弃并停止对外提供入口。
- 接口文档：完整（阶段 2-1/2-2 的 `/api` 路由与 ChatResponse/ChangePlan/Audit 结构）。

## 3. 技术选择

- 框架与版本：Next.js 16.4.4 App Router + React 19.3 + TypeScript strict。
- 样式与组件策略：Tailwind CSS 4 + `@theme` 语义变量；原生 HTML + 轻量自建组件，不引入完整组件库；图标用 lucide-react。
- 数据请求与状态策略：集中 `lib/api`；先使用 React 自带状态，不引入 TanStack Query/Zustand；后端为事实来源。
- 流式通信策略：**本迭代不引入 SSE**，使用「提交 + 等待 + 刷新后重新拉取」；单次诊断 6–10 秒，按钮显示 running/耗时。若后续单次超过 15 秒或需要逐 token 展示，再补 SSE。
- 表单方案：原生受控输入 + 前端校验；不引入表单库。
- 测试方案：Vitest + Testing Library；`package.json` 提供 `lint`、`typecheck`、`test`、`build`；`test` 用 `vitest run` 一次退出。
- 部署环境：本地开发；`proxy.ts` 把 `/api/*` 同源转发到 `BACKEND_URL`（默认 `http://127.0.0.1:8020`）；D9 不部署。

## 4. Agent 状态

| 后端状态 | 前端统一状态 | 用户看到什么 |
| --- | --- | --- |
| 新建会话、无消息 | `idle` | 输入框 + 示例 |
| 请求已发出 | `submitting` | 按钮禁用，禁止重复提交 |
| 模型/工具运行中 | `running` | 当前活动提示 + 已用时间 |
| 变更 `pending_approval` | `waiting_user` | 变更卡片 + 批准/拒绝 |
| 变更 `verified` / 诊断完成 | `succeeded` | 结论、证据、变更结果 |
| `rejected` / 执行失败 | `failed` | 原因 + 可重试/回退 |
| 网络中断 | `disconnected` | 说明请求可能仍在后端执行，提供重新拉取 |
| 刷新后未完成 | `stale` | 重新拉取会话，不判失败 |

- 等待确认：变更卡片「批准 / 拒绝」；批准后由确定性代码执行，前端轮询/重新拉取该 plan。
- 取消、重试：请求进行中可中止 fetch（后端可能仍完成，界面标注「结果可能仍会写入」）；失败可重试；刷新后按 `session_id` 重新拉取。
- 任务 ID 与恢复入口：`/sessions/[sessionId]`；`sessionId` 写入 URL，刷新可恢复；审计页 `/audit` 可回看变更链路。

## 5. 页面与产物

- 核心页面：
  - `/`：新建/最近会话入口（无会话时创建并跳转）；
  - `/sessions/[sessionId]`：工作台——左侧示例/会话，中间对话 + 结论/证据卡片 + 变更卡片，右侧工具调用；
  - `/audit`：审计时间线 + 哈希链校验。
- 核心业务闭环：提问 → 诊断（结论/证据）→ 发起变更 → 批准 → 执行/回读 → 审计回看。
- 产物类型和预览方式：结构化结论卡片、变更计划卡片、审计表格；无文件预览/下载。
- 响应式目标：390 / 768 / 1280 / 1440；手机侧栏改抽屉，审批按钮始终可触达。
- 阶段 3 子阶段规划：
  - **3-1 可运行骨架 + 只读诊断**：Next.js 工程、设计变量、布局/导航、API 客户端、会话页代表页；废弃临时 HTML；验收：桌面/手机基本布局 + 一条真实诊断。
  - **3-2 变更、审批与审计**：变更卡片、批准/拒绝、执行/回读状态、审计页与哈希链校验；验收：完整变更闭环。
  - **3-3 完整交互与质量**：会话恢复/历史、加载/空/错误态、取消/重试、移动端打磨、浏览器检查与截图、清理 Console/Lint/类型问题；验收：390/1440 全流程 + 无阻塞问题。
  - 与《技术适配声明》第 7 节的 3-1～3-3 一致；无合并/省略。

## 6. 偏离本手册的地方

- **不引入 SSE**：本迭代用提交+等待；原因：后端当前是同步请求，单次 6–10 秒，先保证主链路；影响：无逐 token 展示；后续超过 15 秒或需要进度流时补 SSE。
- **临时验收界面废弃**：阶段 3-1 删除或停止 `backend/static/index.html` 入口，不另起平行界面。
- **不引入组件库/状态库**：页面量小，原生 + Tailwind 足够；避免为 MVP 引入不必要依赖。
- **不做登录**：D5 已定本地单用户；业务表已有 `owner_id`，未来加登录不搬数据。
- **执行器是模拟的**：界面必须明确标「模拟执行」，不得让用户误以为真实设备已操作。
