# 阶段 2-3 技术开发文档｜评测与真实模型指标

> 配套文档：`docs/PRD/PRD.md`（V3）、《技术适配声明》、《阶段2-2技术开发文档》。
> 本文档只覆盖阶段 2-3：合成告警评测、Top-1/Top-3、证据覆盖、无数据诚实性、危险动作、token/耗时；不做正式前端（阶段 3）、不上线。

## 一、阶段目标

- 交付范围：把 20 条合成告警 + 2 条无数据样例跑成可复现的评测；输出逐条结果、汇总指标、真实模型冒烟记录。
- 阶段产物：
  - `backend/app/services/evaluation.py` 纯函数打分；
  - `scripts/eval_cases.py` 真实模型评测脚本；
  - `backend/tests/test_eval.py` 打分单测；
  - `docs/evidence/阶段2-3/评测结果.md`、`评测汇总.json`、`冒烟记录.md`；
  - README 增加评测命令与指标口径。
- 验收标准（对齐 PRD 13.1）：
  - Top-1 ≥60%、Top-3 ≥85%；
  - 证据覆盖 100%；
  - 无数据样例 100% 明确说不知道/没有数据；
  - 未审批/危险动作 = 0；
  - 评测过程 token/耗时可见。
- 明确不做：用真实生产告警替换合成样本（需要产品经理提供）、自动调参、正式前端展示。
- 主链路片段：评测集 → 真实模型 → 打分 → 指标表。

## 二、技术适配摘要

- 沿用阶段 2-1/2-2 的 FastAPI + SQLite + DeepSeek 配置。
- 评测时设置 `READ_ONLY_MODE=true`、`POLICY_MODE=read_only`、`FAST_MODE=true`，避免变更工具和多余轮次。
- 打分是纯函数，不调用模型；模型只负责回答。

## 三、技术栈与模型

- 同前：Python 3.12、FastAPI、Pydantic、SQLAlchemy、pytest、httpx。
- 模型：`deepseek-chat`（OpenAI 兼容）；每条用例一次快速诊断调用。
- 不引入：评测平台、向量库、前端。

## 四、环境与配置

- 复用 `backend/.env` 的 `MODEL_API_KEY`；评测脚本只读，不打印 Key。
- 评测使用临时 SQLite，不污染演示数据库。
- 命令：

```bash
backend/.venv/bin/python scripts/eval_cases.py
```

## 五、项目结构（新增）

```text
backend/app/services/evaluation.py   打分纯函数
backend/tests/test_eval.py           打分单测
scripts/eval_cases.py                真实模型评测
docs/evidence/阶段2-3/               评测结果、汇总 JSON、冒烟记录
```

## 六、数据、资产与状态

- `backend/app/data/eval_cases.json`：20 条有数据用例 + 2 条无数据用例（case-21/22）。
- 每条有数据用例：问题、资产、期望根因关键词、期望动作关键词、安全标签。
- 无数据用例：`expected_no_data=true`，期望回答明确说没有该指标/不知道。
- 评测不写业务表，只使用临时 SQLite 保存会话。

## 七、API / 工具设计

- 复用 `/api/sessions/{id}/chat`；不新增产品 API。
- 评测调用真实模型，读取 `assessment`、`tool_calls`、`usage`、`elapsed_ms`。

## 八、Prompt 设计

- 不改系统提示词；沿用阶段 2-1 的简洁诊断与「不知道就说」规则。
- 无数据用例依赖提示词第 2 条和上下文里的 `missing` 指标。

## 九、验收界面

- 不需要新界面；评测结果是 Markdown 表 + JSON。
- 产品经理看 `评测结果.md` 的汇总和逐条表即可。

## 十、测试要求

- 第一层 mock：`test_eval.py` 覆盖关键词命中、正常打分、无数据/危险动作、汇总统计；总测试数 27。
- 第二层真实冒烟：`scripts/eval_cases.py` 跑 22 条，写 `冒烟记录.md`。
- 数据恢复：本阶段不新增持久化结构，沿用 2-2 的 restart-check。

## 十一、验收清单

- [ ] `pytest` 27 条通过；
- [ ] 真实评测 22 条完成，无 HTTP/结构失败；
- [ ] Top-1 ≥60%、Top-3 ≥85%；
- [ ] 证据覆盖 100%；
- [ ] 无数据 100% 说不知道；
- [ ] 危险动作 0；
- [ ] token/耗时记录；
- [ ] README 写明评测命令与指标口径。

## 十二、风险与待确认项

- 合成用例的关键词打分只能近似语义命中；Top-1/Top-3 偏低时应先看逐条，区分是模型判断错还是关键词漏配。
- 真实模型有随机性；同一天重跑可能有 ±1～2 条波动。
- 22 条真实调用会产生少量费用，已在演示预算内。
- 必须由产品经理决定的问题：无。

## 十三、交接给下一阶段

- 阶段 3 把评测指标和变更/审计能力搬进正式 Next.js 前端；评测脚本保留为回归工具。
